# V1.0.6 手动触发与简化障碍物换挡设计

## 1. 目标

V1.0.6 在现有障碍物换挡功能上增加一次性“手动虚拟 P”按钮，并简化自动触发安全门。

- 自动路径：确认 T2CAN 物理刹车已踩下、车辆静止且 T2CAN 真实挡位为 D/R 后，开启一次最长 1000 ms 的虚拟 P 窗口。
- 手动路径：用户点击按钮后，不要求踩刹车；车辆静止且 T2CAN 真实挡位为 D/R 时，开启一次最长 1000 ms 的虚拟 P 窗口。
- 两条路径都只使用刚收到的真实 `0x118` 作为模板；每收到一帧新帧最多发送一帧对应的 P 帧，不缓存、不补发、不定时重放。
- T2CAN 已报告 P 时不发送虚拟 P；N、未知或过期也不发送。

该功能仍属于台架或封闭场地测试功能。当前硬件只有单路 TWAI，真实 `0x118` 与注入的 P 帧会同时存在于同一总线，固件不能拦截或删除原车帧。

## 2. 已批准的触发矩阵

| 条件 | 自动路径 | 手动路径 |
|---|---:|---:|
| 自动障碍物换挡开关开启 | 必须 | 不要求 |
| 用户点击手动按钮 | 不要求 | 必须 |
| T2CAN 物理刹车有效且已踩下 | 必须 | 不要求 |
| T2CAN 车速有效且确认静止 | 必须 | 必须 |
| T2CAN 真实挡位有效且为 D/R | 必须 | 必须 |
| CAN Write 状态已知且开启 | 必须 | 必须 |
| CAN 在线 | 必须 | 必须 |
| 非 OTA、非重启准备状态 | 必须 | 必须 |
| 新的、结构与校验正确的真实 `0x118` | 必须 | 必须 |
| 最长窗口 | 1000 ms | 1000 ms |

“刹车确认”只使用 T2CAN BrakeState 中的物理刹车 `physicalKnown && physicalFresh && physicalPressed`，不再要求系统刹车、双源一致、150 ms 保持或顶层 `brakePressed`。

“车辆静止”继续使用 T2CAN 已计算的 `speedFresh && stationaryConfirmed`。发送端当前静止定义为 UI 原始车速为 0 且解码绝对车速不超过 0.2 km/h。

“T2CAN 挡位有效”定义为 `gearFresh` 且 `realGear` 为 D 或 R。本机 `0x118 Byte2` 不再参与触发判定；它只作为待修改原帧中的一个字段存在。生成虚拟 P 时覆盖 Byte2 为 `0x32`、Byte6 为 `0x00`，然后重算 Byte0 校验和。

## 3. T2CAN 控制快照与 BLE 延迟

T2CAN BrakeState 仍以约 50 ms 周期发送。WiFi-NAG 对用于刹车、车速和挡位判断的控制快照采用统一的 500 ms 本地接收年龄上限：

- 年龄不超过 500 ms 且各字段自己的 fresh 位有效，才可启动或维持窗口。
- 超过 500 ms 立即停止当前窗口。
- 过期不能自动触发新窗口；自动路径必须重新看到明确物理刹车释放后再等待下一次踩下。
- 500 ms 仅用于容忍 BLE 调度抖动，不允许在断链后长期沿用最后一次 D/R、静止或踩刹车状态。

## 4. BrakeState 原因码兼容修复

当前 T2CAN 发送端与 WiFi-NAG 接收端的原因码定义错位，导致 Active 和确认释放包被计入 `Brake bad`，控制快照无法刷新。V1.0.6 必须先让接收端与实际 T2CAN 线协议一致：

| 线值 | T2CAN 语义 |
|---:|---|
| 0 | Active |
| 1 | Confirmed brake release |
| 2 | Brake unknown or stale |
| 3 | Brake source mismatch |
| 4 | Brake fallback |
| 5 | Brake hold pending |
| 6 | Gear unknown or stale |
| 7 | Gear not D/R |
| 8 | Speed unknown or stale |
| 9 | Vehicle moving |
| 10 | Feature or runtime disabled |
| 11 | Session resync with confirmed release |

接收端继续拒绝结构矛盾包，但必须按上述线值解释原因：

- `brakePressed=1` 只允许原因 0，且不能带 release-tail。
- `releaseConfirmed=1` 允许原因 1 或 11，且必须满足发送端的明确释放字段组合。
- 其他停止原因不能宣称 `releaseConfirmed=1`。
- 增加跨仓库契约回归测试，使用 T2CAN 已编码的 Active、确认释放、冲突、过期与移动样本验证 WiFi-NAG 解码结果。

## 5. 单一控制器与优先级

继续由 `ObstacleShiftController` 和 CAN 任务独占虚拟 P 发送，不能新建第二个 CAN 写入者。

控制器增加窗口触发源：

- `NONE`
- `AUTOMATIC_BRAKE`
- `MANUAL_BUTTON`

优先级与互斥规则：

1. 任一窗口活动时，不能启动第二个窗口。
2. 自动窗口活动时点击手动按钮，API 返回 busy，不重启或延长当前窗口。
3. 手动窗口活动时出现自动条件，不启动自动窗口。
4. 手动窗口期间若物理刹车已踩下，将本次踩刹车视为已消费；手动窗口结束后不能无缝接上自动窗口，必须先明确释放再重新踩下。
5. 任一路径的 1000 ms 窗口完成后都不会自动续开。

## 6. 自动路径状态机

自动路径保留“一次踩刹车只触发一次”语义，但不再使用旧的 500 ms 窗口、双源一致、系统刹车、150 ms 保持和顶层 Active eligibility。

```text
WAIT_RELEASE
  + 新鲜的物理刹车明确释放
  -> ARMED

ARMED
  + 物理刹车有效且踩下
  + 静止有效
  + T2CAN D/R 有效
  -> 1000 ms AUTOMATIC_BRAKE 窗口

窗口完成或提前停止
  -> LATCHED

LATCHED
  + 新鲜的物理刹车明确释放
  -> ARMED
```

## 7. 手动按钮语义

WebUI 在障碍物换挡卡片中增加醒目的“手动虚拟 P（1 秒）”按钮，而不是持久化 toggle。

- 点击时通过独立 POST API 请求一次手动窗口。
- 请求不写入 NVS；重启后不存在残留手动状态。
- API 在调用时检查 CAN Write、CAN 在线、OTA/重启、T2CAN 静止、T2CAN D/R 和控制快照新鲜度。
- 条件不满足时拒绝请求并返回具体原因，不进入等待或排队状态。
- 请求成功后按钮进入 1000 ms 活动态，窗口结束或提前停止后自动复位。
- 页面断开不会延长窗口；固件中的单调时钟决定结束时间。

## 8. `0x118` 数据路径

手动与自动窗口使用相同的数据路径：

1. CAN 任务收到一帧数据。
2. 排除本机最近发送的虚拟 P 回环。
3. 只接受标准数据帧、ID `0x118`、DLC 8、现有校验公式正确的帧。
4. 不再要求本机 Byte2 能解析为 D/R；T2CAN 挡位是唯一挡位权威。
5. 确认当前窗口活动且全部维持门仍有效。
6. 复制当前真实帧，写入 Byte2=`0x32`、Byte6=`0x00`，重算 Byte0。
7. 立即调用 CAN 驱动发送。
8. 不保存待重试帧；失败帧永不重放。

## 9. 立即停止条件

活动窗口中任一条件成立都立即停止：

- 达到 1000 ms；
- T2CAN 控制快照年龄超过 500 ms；
- `speedFresh` 或 `stationaryConfirmed` 失效；
- T2CAN 挡位离开 D/R，包括已经为 P；
- CAN Write 关闭或状态未知；
- CAN 离线；
- OTA 开始或进入重启准备；
- CAN 发送失败；
- BLE 会话断开或控制快照失效。

自动窗口还在物理刹车明确释放时提前停止。手动窗口不要求刹车，因此刹车变化不影响已经启动的手动窗口。

停止后不发送缓存帧。自动路径进入锁存并等待明确释放；手动路径结束并自动复位。

## 10. WebUI 与诊断

状态 API 和障碍物换挡卡片增加：

- 当前触发源：无 / 自动刹车 / 手动按钮；
- 手动请求是否可用；
- 手动请求被拒绝的具体原因；
- 窗口剩余时间，最大显示 1000 ms；
- T2CAN 控制快照年龄；
- T2CAN 物理刹车、车速有效/静止、真实挡位；
- 自动窗口次数、手动窗口次数；
- P 发送成功数和失败数；
- 当前停止/阻止原因。

界面说明必须明确：手动按钮不要求踩刹车，但仍要求 T2CAN 静止和 D/R；T2CAN 已为 P 时不会注入；真实与虚拟 `0x118` 会在同一总线上共存。

## 11. 测试要求

### 11.1 协议契约

- T2CAN Active 样本不再增加 `Brake bad`，物理刹车、速度和挡位字段正确发布。
- 确认释放值 1 和会话重同步释放值 11 均按对应语义接受。
- 冲突、过期、移动和禁用原因显示正确。
- 结构矛盾、保留位、非法挡位来源和非法速度组合仍被拒绝。

### 11.2 自动路径

- 物理刹车踩下 + 静止 + D/R 启动一次 1000 ms 窗口。
- 不再要求系统刹车、双源一致、150 ms hold 或顶层 `brakePressed`。
- 同一次踩下不能自动续开第二个窗口。
- 明确释放后才能重新触发。
- 移动、P/N/未知、快照过期和技术门失效立即停止。

### 11.3 手动路径

- 不踩刹车但静止 + D/R 时按钮可启动一次 1000 ms 窗口。
- 移动、速度无效、P/N/未知、快照过期或技术门失效时请求被拒绝。
- 窗口不能自动续开，结束后必须再次点击。
- 手动窗口与自动窗口互斥。
- 手动按钮和活动状态不持久化。

### 11.4 `0x118`

- 本机 Byte2 未知但 T2CAN D/R 时仍能生成正确 P 帧。
- 错误 ID、DLC、校验和和本机回环均不发送。
- 每个真实新帧最多对应一个发送尝试。
- TX 失败立即停止且失败帧不重放。

### 11.5 WebUI 与构建

- 页面源文件、生成的 gzip 产物和回归断言同步。
- API 返回稳定的成功、busy 和安全门拒绝结构。
- Native 控制器测试、Python 回归测试和 ESP32-S3 PlatformIO 正式构建全部通过。
