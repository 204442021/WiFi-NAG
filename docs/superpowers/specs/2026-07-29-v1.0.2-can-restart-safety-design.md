# WIFI-NAG V1.0.2 CAN 安全重启设计

## 目标

在 V1.0.1 基线上修复 OTA 完成或网页手动重启时，车辆偶发出现 AEB、牵引力控制、车身稳定控制及能量回收相关警报的问题，同时保持现有 Nag、WiFi、DNS、OTA 分区和页面功能不变。

## 根因范围

V1.0.1 的“CAN 写入关闭”只禁止 Nag 业务帧发送，底层 TWAI 仍以 Normal 模式参与总线；软件重启前也没有统一的 CAN 安全退出。启动阶段还会因为重复设置相同过滤器而重复停止、卸载和启动 TWAI。上述时序窗口具有偶发性，符合“不是每次重启都报警，但报警发生在重启时”的实车现象。

## 设计

### 1. 真正的只读模式

TWAI 驱动首次启动固定使用 Listen Only，发送队列长度设为 0。运行时由现有 `canActive` 状态同步硬件模式：关闭时保持 Listen Only，开启时才切换为 Normal。Nag 业务开关和底层 TWAI 模式形成双重门控。

### 2. 安全切换与安全重启

TWAI 驱动增加统一接口：

- `setWriteEnabled(bool)`：在 Listen Only 与 Normal 之间切换；状态未变化时立即返回，不重复重装。
- `prepareForRestart()`：设置关机锁、等待短暂的总线空闲窗口、停止并卸载 TWAI，随后把 TX GPIO 固定为 recessive 高电平。

ESP-IDF 注册 shutdown handler，确保网页重启和 OTA 成功后的 `esp_restart()` 都经过同一条安全退出路径。该流程必须幂等，重复调用不会恢复发送或重新安装驱动。

### 3. 启动顺序

TWAIDriver 构造后立即把 TX GPIO置为 recessive。过滤器在驱动首次 `init()` 前写入，避免安装后立即重装。Dashboard 后续重复设置同一个过滤器时由驱动识别为无变化并直接返回。

### 4. OTA 写入期

当 `Update.isRunning()` 为真时，CAN 任务先同步到只读模式再暂停业务处理。启用 TWAI ISR IRAM 配置和 Listen Only dominant errata 修复，降低 Flash 写入和监听错误对总线的影响。

## 不包含的改动

- 不改 Nag 0x370 数据、计数器、校验和和扭矩算法。
- 不改 WiFi、DNS、NAPT、OTA 分区表和网页布局。
- 不依赖修改微雪板 TJA1051 的 S 引脚硬件连接。
- 不增加新的车辆控制功能。

## 验收标准

1. 固件内部版本统一为 `V1.0.2`。
2. CAN 写入关闭时，TWAI 实际运行于 Listen Only，TX 队列关闭。
3. CAN 写入开启时可恢复现有 Nag 发送能力。
4. OTA 和手动重启均通过 shutdown handler 安全退出 CAN。
5. 启动时过滤器在首次安装前配置，相同过滤器不会重复重装驱动。
6. Python 回归测试、三个 native PlatformIO 测试和 ESP32-S3 固件编译全部通过。
7. GitHub Release `V1.0.2` 上传 `WIFI-NAG-V1.0.2-OTA.bin`，更新说明只描述用户可感知的稳定性变化，不公开实现细节。
