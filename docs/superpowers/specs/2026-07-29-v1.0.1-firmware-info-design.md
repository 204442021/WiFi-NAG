# WiFi-NAG V1.0.1 固件信息设计

## 目标

在固件更新卡片只显示三项信息：

1. 固件版本：`V1.0.1`
2. 当前运行分区：`OTA_0` 或 `OTA_1`
3. OTA 上传时间：由执行上传的手机/浏览器提供本地时间，OTA 成功后写入 NVS

## 版本来源

仓库根目录 `VERSION` 是唯一版本来源，内容固定为 `V1.0.1`。

- PlatformIO 构建脚本继续从 `VERSION` 注入 `FIRMWARE_VERSION`。
- 根 `CMakeLists.txt` 从同一文件设置 ESP-IDF `PROJECT_VER`，使固件二进制内部 `esp_app_desc.version` 同样为 `V1.0.1`。
- WebUI 显示优先读取固件内部版本，避免页面版本与二进制版本不一致。

## 数据流

- 当前分区：后端通过 `esp_ota_get_running_partition()` 获取运行分区，并按 APP OTA subtype 显示为 `OTA_0` 或 `OTA_1`。
- OTA 上传时间：浏览器开始上传时生成本地 `YYYY-MM-DD HH:mm:ss`，作为 `/update` 查询参数发送；仅当 `Update.end(true)` 成功后写入 NVS 键 `ota_time`。
- `/system_status` 返回 `firmware`、`ota_partition`、`ota_time`，页面加载时读取一次并显示。

## 边界与异常

- 时间缺失或格式不合法时不写入 NVS，页面显示“未记录”。
- OTA 失败时不得覆盖上一次成功上传时间。
- 从不具备该功能的旧固件首次升级到 V1.0.1 时，旧页面不会发送时间，因此首次可能显示“未记录”；从 V1.0.1 开始进行的后续 OTA 会正常记录。
- 不增加在线 OTA、自动检查更新、Boot 次数、OTA 次数、Git Commit 或其他字段。

## 验证

- 回归测试检查版本唯一来源、页面三项字段、NVS 成功写入条件以及 OTA 分区映射。
- 运行现有 Python 与 PlatformIO native 测试。
- 编译 ESP32-S3 固件，并确认生成二进制包含内部版本 `V1.0.1`。
