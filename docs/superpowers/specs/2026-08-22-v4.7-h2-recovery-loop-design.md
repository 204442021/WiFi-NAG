# V4.7-V13 H2 Recovery Loop Design

## Goal

Replace the V4.6 assumption that H0-H2 are all successful maintenance states with a feedback loop that treats H2 as a timed maintenance failure, resets transmission, corrects to HOS <= 1, and verifies that maintenance can hold HOS <= 1.

## Confirmed state machine

1. With maintenance enabled, H0/H1 uses preventive torque `1.70..1.80 Nm`.
2. Preventive rest `0/0 s` disables the rest phase and keeps maintenance injection continuous. Non-zero ranges retain the existing send/rest cycle.
3. A continuous fresh H2 starts an adjustable timer, default `3.0 s`. Returning to H0/H1 resets the timer. Stale/invalid feedback never accumulates H2 time.
4. H2 reaching the timer, or H3-H5 at any time, starts a full no-send reset pause, default `0.5 s`. A reset pause of `0 s` skips the pause and enters correction immediately.
5. Correction uses the existing adjustable `1.80..2.00 Nm` send/pause windows. A corrective pause of `0/0 s` disables that pause instead of creating a stuck zero-duration phase.
6. H2 is not correction success. Correction exits only after two consecutive fresh H0/H1 observations.
7. After correction, maintenance injection resumes and H0/H1 must remain continuously stable for an adjustable `5.0 s`. H2 resets the stability timer and uses the same H2 persistence threshold; H3-H5 restarts correction immediately. A stability duration of `0 s` disables this probation.
8. H6-H15, stale DAS, invalid frames, disabled NAG, and CAN Write OFF retain fail-closed behavior. Corrective torque remains hard-clamped to `+/-2.00 Nm`.
9. Disabling the maintenance layer preserves monitor-only H0-H2 behavior; H2 timeout recovery is inactive, while H3-H5 correction remains active.

## Configuration and zero semantics

| Field | Default | Zero behavior |
|---|---:|---|
| `restMinMs/restMaxMs` | `0/0` | Both zero disable preventive rest |
| `h2PersistenceMs` | `3000` | First fresh H2 observation triggers recovery |
| `preCorrectionPauseMs` | `500` | Skip the reset pause |
| `correctivePauseMinMs/correctivePauseMaxMs` | `1000/2000` | Both zero disable corrective pause |
| `stabilityVerifyMs` | `5000` | Accept H0/H1 recovery immediately |

For range fields, zero-disable requires both endpoints to be zero. Mixed zero/non-zero ranges are invalid API input so their meaning cannot be ambiguous.

## Diagnostics

The existing phase and remaining-time telemetry must expose the new phases `h2-pending`, `pre-corrective-pause`, and `stability-verify`. No local transmit result may be labeled as DAS acknowledgement.

## Validation

Native tests must cover every transition, timer reset, zero-duration bypass, stale/fault exit, and repeated failed handoff. A bounded deterministic sequence test must prove that every non-fault state either emits an eligible action or reaches a different state when its configured feedback/time condition occurs; zero-duration phases may not trap execution.
