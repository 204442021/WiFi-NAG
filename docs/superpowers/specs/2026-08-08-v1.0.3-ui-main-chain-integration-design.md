# WiFi-NAG V1.0.3 UI 主链一体化设计

## 背景

当前根页面依次经过外层 WiFi-NAG Shell、`/legacy-dashboard` BLE 组装页、`/dashboard` gzip 页面，以及运行时 BLE 卡片注入和外层跨文档 DOM 调整。NAG sweep 又通过第二个 gzip member 注入脚本。该结构让页面完整性依赖多个路由、动态插入点、iframe 和浏览器对拼接 gzip 的兼容行为。

本设计以用户提供的《WiFi-NAG V1.0.3 UI 主链一体化修改方案》为批准基线，将页面改为由 `mcpDashboardSetup()` 注册并直接返回的单一静态主页面。

## 目标

- `GET /` 直接返回唯一完整的 `DASH_HTML_GZ`。
- 顶部栏、四个主卡片、NAG sweep 控件和 BLE 控件均静态存在于 `mcp2515_dashboard_ui.src.h`。
- 页面不再使用 iframe、`document.write()`、`fetch('/dashboard')`、动态卡片创建或跨文档 DOM 搬运。
- BLE、NAG sweep、Wi-Fi、系统状态、日志和固件更新继续通过各自 API 工作。
- 任一局部 API 失败只更新对应区域的错误状态，不破坏或刷新整页。
- `/dashboard` 与 `/legacy-dashboard` 保留为兼容入口，但只返回到 `/` 的无缓存 302 重定向。

## 非目标

- 不改变 BLE 协议、配对、绑定、状态同步或障碍物转发逻辑。
- 不改变 NAG sweep 的 NVS 命名、默认值、取值范围或后端 API。
- 不改变 Wi-Fi、STA-AP 网关、DNS、系统状态、日志、OTA 和 CAN/NAG 业务 API。
- 不扩展新的 UI 模式；WiFi-NAG 主页面固定使用 `wifi-nag ui-phone ui-shell` 布局。
- 不进行与主链一体化无关的后端重构。

## 页面架构

`include/web/mcp2515_dashboard_ui.src.h` 是唯一可编辑页面源。页面由以下静态结构组成：

1. `#wifi-nag-header`：品牌、CAN 状态、语言、主题和重启动作。
2. `#wifi-nag-main`：最大宽度约 920px，桌面居中，移动端保留 10–14px 边距。
3. `#config-card`：`#config-hardware-section` 和 `#ble-bridge-section`。
4. `#wifi-config-card`：`#wifi-hotspot-section`、`#wifi-internet-section` 和 `#gateway-section`。
5. `#system-card`：`#status-panel`、系统网格和 `#debug-log-section`。
6. `#firmware-update-card`：固件信息与手动 OTA 控件。
7. 原确认弹窗、安全提示和警告栏继续保留。

主卡片标题、图标、meta 和 chevron 在 HTML 中直接声明。初始化不再调用 `orderDashboardCards()`、`initCardMinimizers()` 或 `initSubsectionMinimizers()` 来塑造 WiFi-NAG 主页面。

## 交互设计

### 主卡片折叠

`initWifiNagAccordion()` 初始化四个 `.ui-main-card` 为折叠状态。点击某个卡片的直接子 `.card-hdr` 时：

- 折叠卡片会展开，其他主卡片全部折叠。
- 已展开卡片可再次折叠。
- `aria-expanded`、卡片 `collapsed` class 和 chevron 方向保持一致。
- `.sys-monitor` 内的点击不触发卡片折叠。

`setCollapsedPanel()` 遇到 `.ui-main-card` 时委托给 `setMainCardExpanded()`，子区块仍保留原有兼容行为。

### NAG sweep

`#nag-sweep-row` 静态位于 `#can-write-row` 与 `#nag-mode-row` 之间。页面脚本提供 `normalizeNagSweepRange()`、`renderNagSweep()`、`previewNagSweepRange()`、`loadNagSweepRange()`、`saveNagSweepRange()` 和 `initNagSweepUi()`：

- min/max 限制为 1–30 秒，反向输入自动交换。
- 初始默认 5–8 秒，加载失败保留默认值并只更新 sweep 局部提示。
- 保存按钮在请求期间禁用；成功后采用服务端返回值；失败后恢复按钮并显示局部错误。
- 语言切换后直接调用 `renderNagSweep()`。

### BLE

`#ble-bridge-section` 与所有既有控件 ID 静态位于 `#config-card`。页面脚本保留状态加载、配置、配对、解绑和手动刷新行为，并用单一 2000ms 定时器刷新；页面隐藏时跳过请求。

BLE 请求失败时只更新 `#ble-card-meta` 和 `#ble-action-msg`。配置、配对或解绑失败不移动 DOM、不刷新页面，也不影响其他卡片。

### 主题和语言

主题继续使用 `localStorage.theme` 与 `localStorage.themeMode`，并复用 `toggleTheme()` / `applyTheme()`。语言继续复用 `toggleLanguage()`，按钮和新增 NAG sweep 文案随语言重新渲染。

## 后端与路由

`src/main.cpp` 按以下顺序初始化页面相关组件：

1. `bleBridgeRegisterApiRoutes()` 先注册 BLE API 以及权威 `/config`、`/disable` 处理器。
2. `mcpDashboardSetup()` 注册根页面及其他 dashboard API。
3. `bleBridgeAfterDashboardSetup()` 配置 BLE/NAG 回调并启动 BLE client。

`include/ble/bridge_webui.h` 删除页面 Shell、UI JavaScript 和页面路由，只保留 `/ble_status`、`/ble_config`、`/ble_pair`、`/ble_unbind`、`/config` 和 `/disable`。

`include/web/mcp2515_dashboard.h` 继续由 `handleRoot()` 直接发送 `DASH_HTML_GZ`，并新增 `/dashboard`、`/legacy-dashboard` 到 `/` 的 302 兼容重定向。

`NagSweepWebServer` 只负责加载/保存 sweep NVS、注册 GET/POST `/api/nag-sweep` 和返回 JSON。它不再覆盖 `sendRaw()`，也不再分配或拼接页面缓冲区。

## 生成链

`scripts/minify_dashboard.py` 只执行：

`mcp2515_dashboard_ui.src.h` → 提取 HTML → 压缩 CSS/JavaScript/HTML → gzip → `mcp2515_dashboard_ui.base.h`

脚本移除 NAG patch 输入、输出和第二 gzip member 逻辑，并新增 `--check`：在内存中生成预期内容后与当前 `base.h` 比较；一致退出 0，不一致输出 `generated payload is stale` 并退出非零，且检查模式不写文件。

## 测试与验收

回归测试必须覆盖：

- 根路由只由 `mcp2515_dashboard.h` 注册。
- 旧页面地址只重定向，不再组装页面。
- 源页面和生成页面均包含全部核心区域，并验证各子区块静态归属。
- 页面源、BLE 后端、sweep 后端和生成脚本中不存在 iframe、`document.write()`、Shell、动态插入、patch gzip 或页面缓冲拼接残留。
- BLE 与 sweep API 仍存在，新增脚本函数具有局部错误处理。
- `minify_dashboard.py --check` 可证明生成产物同步。
- 全部 Python 回归测试、native PlatformIO 测试和 ESP32-S3 固件构建通过。

设备级最终验收为打开 `http://100.100.1.1/` 后一次 HTML 请求得到完整后台，且不再请求 `/legacy-dashboard`、`/dashboard` 或 `/ble_ui.js`。在没有连接实体设备的环境中，此项作为待实机确认的人工验收，不以静态测试冒充。
