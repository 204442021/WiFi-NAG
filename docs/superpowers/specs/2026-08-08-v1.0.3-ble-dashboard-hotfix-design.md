# V1.0.3 BLE 后台加载热修复设计

## 1. 目标

在不重构现有 WebUI 三层路由的前提下，修复 BLE 卡片插入失败导致整个后台空白的问题，并确保以后 BLE 页面组合异常时，NAG、Wi-Fi、系统状态和 OTA 等原后台功能仍可正常显示。

基线分支：`V1.0.3`

基线提交：`06c66b0083265397342ffd44bde0f0015f9f7b7b`

工作分支：`V1.0.3-BLE后台热修复`

## 2. 已确认根因

`include/ble/bridge_webui.h` 中的 BLE 页面组装器先请求 `/dashboard`，再使用完全匹配的字符串：

```html
<div class="subsec" id="wifi-hotspot-section"
```

作为 BLE 卡片插入点。

实际生成并压缩后的页面使用无引号属性：

```html
<div class=subsec id=wifi-hotspot-section data-subkey=config-wifi-hotspot>
```

因此 `html.includes(marker)` 返回 false，代码抛出 `BLE card insertion point missing`，并且没有把已成功获取的原后台 HTML 写回页面，最终只显示错误文字。

## 3. 采用方案

采用方案 B：最小热修、兼容压缩格式、失败放行。

不在本次热修中取消外层 iframe、BLE 中间组装页或 `/dashboard` 原后台路由；这些属于后续版本的 WebUI 单页化重构范围。

## 4. 页面组合逻辑

### 4.1 插入位置定位

BLE 页面组装器不再依赖属性引号、属性顺序或 class 的精确字符串形式。

使用唯一元素 ID `wifi-hotspot-section` 定位对应 `<div>` 开始标签，必须兼容：

- `id="wifi-hotspot-section"`
- `id='wifi-hotspot-section'`
- `id=wifi-hotspot-section`
- `id` 与 `class` 属性顺序变化
- 标签内出现额外属性

找到开始标签后，在该标签之前插入 BLE 卡片，使页面顺序继续保持：

```text
NAG/CAN 设置
→ BLE 联动
→ Wi-Fi 热点
→ Wi-Fi 上网
→ 网关
```

### 4.2 失败放行

当 `/dashboard` 已成功返回，但 BLE 插入位置不存在时：

1. 不抛出阻断页面的异常；
2. 不显示全屏“页面加载失败”；
3. 原样写入已获取的后台 HTML；
4. 仅通过 `console.warn` 记录 BLE 卡片未插入；
5. NAG、Wi-Fi、系统状态和 OTA 页面必须继续可用。

只有在 `/dashboard` 请求本身失败、HTTP 状态异常或无法取得任何原后台 HTML 时，才保留加载失败提示。

### 4.3 BLE 功能隔离

本次修改不改变：

- BLE 扫描、配对、绑定和状态同步逻辑；
- `/ble_status`、`/ble_config`、`/ble_pair`、`/ble_unbind` 接口；
- NAG 权威状态同步；
- 0x255 / 0x12B 障碍物数据转发；
- CAN 快速路径、过滤器和任务优先级；
- Wi-Fi、DNS、OTA 和系统状态后端逻辑。

## 5. 测试设计

新增 BLE 页面组合回归测试，读取真实文件：

- `include/ble/bridge_webui.h`
- `include/web/mcp2515_dashboard_ui.base.h`

测试必须验证：

1. 实际生成页面包含压缩后的 `id=wifi-hotspot-section`；
2. BLE 插入定位逻辑同时接受带引号和无引号的 ID；
3. 属性顺序变化不影响定位；
4. 插入后 BLE 卡片位于 Wi-Fi 热点卡片之前；
5. 找不到插入点时返回原 HTML，而不是抛出 `BLE card insertion point missing`；
6. 旧的阻断式异常文本不得继续作为页面控制逻辑存在；
7. 原有固件信息与 Wi-Fi 回归测试要求不得降低。

完整验证阶段执行现有 V1.0.3 发布门禁：

```text
python -m compileall -q scripts test
python -m unittest discover -s test -p "test_*regression.py" -v
pio test -e native_nag
pio test -e native_nag_sweep
pio test -e native_twai
pio test -e native_log_buffer
pio test -e native_ble
pio run -e wifi_nag_ESP32_S3_CAN
```

## 6. 提交与发布

修复代码先提交到 `V1.0.3-BLE后台热修复`，确认修改范围和测试结果后合入 `V1.0.3`。

正式发布必须以修复后的 `V1.0.3` 新提交 SHA 为唯一源码目标，重新生成：

- `WIFI-NAG-V1.0.3-OTA.bin`
- `WIFI-NAG-V1.0.3-FACTORY-16MB.bin`
- Manifest、SHA256、刷写说明

随后覆盖 GitHub Release `V1.0.3` 中的同名资产，并将 `V1.0.3` tag 更新到修复后的正式源码提交。不得复用旧提交 `06c66b0083265397342ffd44bde0f0015f9f7b7b` 构建出的固件。
