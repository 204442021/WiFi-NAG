# WIFI-NAG V1.0.3 CAN 架构结论与随机扫动时间设计

## 决策修订

本文件以用户最终确认的范围为准，替代本文件早期版本中关于多级 CAN 优先级、通用 TX 调度器和大规模底层拆分的建议。

WIFI-NAG 当前只发送一种 CAN 帧：`0x370 / 880` Nag echo，后续也不计划增加其他 CAN 发送功能。因此现阶段不建设 S0/P0/P1/P2 多级业务队列，也不做 RX/业务/TX 的大规模任务拆分。

现有架构整体可继续使用，保留以下安全能力：

- ESP32-S3 原生 TWAI，500 kbit/s。
- 独立 CAN 任务。
- CAN Write 关闭时使用 Listen Only。
- OTA 和重启前安全停止 TWAI。
- TX GPIO 保持 recessive。
- Bus-Off 冷却恢复。
- 真实 `0x370` 原帧复制、counter+1、checksum 重算和自发帧过滤。

## 本次唯一功能改动

在 CAN Write 下增加“扫动时间”范围：

- 可设置范围：`1–30 秒`。
- 默认值：`5–8 秒`。
- 最短值大于最长值时自动交换。
- 越界值自动限制在 `1–30 秒`。
- 设置写入 NVS，重启和固件更新后保留。

## 发送时序

1. CAN Write 从关闭切换为开启。
2. 收到下一帧真实 `0x370` 后立即写入一次。
3. 每次写入完成后，在最短和最长时间之间重新生成一个随机等待时间。
4. 等待期间只接收实时帧，不累计、不补发。
5. 随机等待到期后，使用当时最新收到的真实 `0x370` 写入一次。
6. 重复步骤 3–5。
7. CAN Write 关闭后停止写入；再次开启后重新执行“下一帧立即写入”。

## 模式行为

- A：每次实际写入保持固定 `+1.80 Nm`。
- A_V2：保持“随机扭矩”；只在实际写入发生时，在已设置扭矩范围内生成一个新随机值。
- 删除 A_V2 独立固定 `2000 ms` 扭矩扫动周期。
- A 和 A_V2 共用同一组随机扫动时间。

## 实现边界

本次不做：

- CAN 多优先级。
- 通用发送调度器。
- 新增任何其他车辆控制帧。
- 修改 WiFi、DNS、NAPT、OTA 产品逻辑。
- 测试、编译或发布；这些步骤必须等待用户后续确认。
