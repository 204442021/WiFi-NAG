# V1.0.6 Manual and Simplified Obstacle Shift Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 兼容 T2CAN 当前 BrakeState 线协议，在 WIFI-NGA 中实现物理刹车自动触发与无需刹车的手动 1 秒虚拟 P 窗口，完成 WebUI、诊断、版本、构建和发布固件。

**Architecture:** BLE 任务只校验并发布 T2CAN 控制快照；WebUI 只提交原子递增的手动请求代号；CAN 任务中的单一 `ObstacleShiftController` 消费请求、推进自动/手动互斥状态机，并独占 `0x118` 虚拟 P 发送。T2CAN 挡位与静止状态是车辆条件权威，本机 `0x118` 只提供新鲜帧模板。

**Tech Stack:** C++17、ESP-IDF 6.0.1、PlatformIO Core 6.1.19、Unity native tests、Python `unittest`、ESP32-S3 TWAI、嵌入式 HTML/JavaScript。

## Global Constraints

- 只修改 `C:\Users\wxy\Desktop\WIFI-NGA\.worktrees\V1.0.6`；不修改 `C:\Users\wxy\Desktop\T2CAN-B`。
- 自动路径需要 T2CAN 物理刹车有效且踩下、静止有效、T2CAN D/R；不要求系统刹车、双源一致、150 ms hold 或顶层 `brakePressed`。
- 手动路径不要求刹车，但必须静止有效且 T2CAN D/R。
- 两条路径均为一次性 1000 ms 窗口，不能自动续开；T2CAN 已为 P 时不发送。
- T2CAN 控制快照本地年龄上限为 500 ms。
- CAN Write、CAN 在线、OTA/重启、真实新 `0x118` 结构/校验和、自发回环保护必须保留。
- 每个真实新 `0x118` 最多一次发送尝试；不得缓存、补发或重放失败帧。
- 手动请求不持久化；固件重启后不存在活动请求。
- 所有 PlatformIO 命令显式设置 `PLATFORMIO_CORE_DIR=D:\DevData\SDKs\PlatformIO` 和 `PLATFORMIO_BUILD_CACHE_DIR=D:\DevData\BuildCache\PlatformIO`。
