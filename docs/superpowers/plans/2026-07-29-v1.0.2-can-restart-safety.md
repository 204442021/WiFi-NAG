# WIFI-NAG V1.0.2 CAN Restart Safety Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Eliminate intermittent vehicle alerts caused by WIFI-NAG OTA/manual software restart while preserving all V1.0.1 functions.

**Architecture:** Boot the TWAI controller in Listen Only, synchronize the physical controller mode with the existing CAN Write state, and add one idempotent shutdown path that quiesces TWAI and holds TX recessive before `esp_restart()`. Configure filters before first driver installation and make repeated identical filter requests a no-op.

**Tech Stack:** ESP32-S3, ESP-IDF 6.0.1 legacy TWAI driver, FreeRTOS, PlatformIO, Python unittest, GitHub Actions.

## Global Constraints

- Base branch is `V1.0.1`; implementation branch is `V1.0.2`.
- Internal and displayed firmware version must be exactly `V1.0.2`.
- Do not change Nag payload generation, WiFi/DNS/NAPT behavior, OTA partition layout, or WebUI layout.
- Default boot behavior remains CAN Write OFF.
- Release asset name is `WIFI-NAG-V1.0.2-OTA.bin`.
