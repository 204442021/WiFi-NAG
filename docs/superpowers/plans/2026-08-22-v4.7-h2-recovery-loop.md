# V4.7-V13 H2 Recovery Loop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the approved H2 timeout, reset pause, HOS <= 1 correction exit, and five-second maintenance stability loop without changing the CAN echo architecture or the 2.00 Nm corrective hard cap.

**Architecture:** Extend `NagAdaptiveController` with three explicit phases and three scalar timers while keeping 0x39B read-only and 0x370 echo generation unchanged. Carry the new parameters atomically through the existing exchange, HTTP API, NVS, WebUI draft/save contract, and generated embedded dashboard. Use deterministic native tests to prove that zero-duration bypasses and repeated handoff failures cannot trap the controller in a non-progressing phase.

**Tech Stack:** C++17, PlatformIO native + Unity, ESP-IDF 6.0.1, ESP32-S3 TWAI, Python unittest, embedded HTML/JavaScript, NVS Preferences.

**Spec:** `docs/superpowers/specs/2026-08-22-v4.7-h2-recovery-loop-design.md`

## Global Constraints

- Branch from `V4.6-V13` commit `514cc57a9029f2a16172c24a9d21376927b2052d` into local and remote `V4.7-V13`.
- Do not modify the 0x370 counter/checksum echo architecture, 0x39B read-only role, direction confirmation, BLE, Wi-Fi, gateway, obstacle shift, or unrelated CAN filters.
- Preventive torque remains `1.70..1.80 Nm`; corrective torque remains `1.80..2.00 Nm` with an immutable `+/-2.00 Nm` cap.
- `0/0` disables a ranged no-send phase; scalar pause `0` skips that pause.
- Deliver OTA and exact 16 MiB full-flash images with SHA-256 values and filenames containing the final short commit SHA.
